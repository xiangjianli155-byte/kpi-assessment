# KPI 网站共享上传设计

## 目标

让所有访客直接从公开 KPI 网站上传每周的 Excel 数据。每次上传作为新一批加入共享历史；所有访客看到相同的累计数据。任何访客都可以追加数据，不会覆盖旧批次。

## 当前问题

现有文件上传器只在上传者当前会话中生效。它不会保存文件，也不会让其他访客看到上传内容。项目已放入私有 GitHub 仓库 `xiangjianli155-byte/kpi-assessment`，仓库尚未包含业务 Excel。

## 方案

- Streamlit 网站继续公开供所有人查看，GitHub 源仓库保持私有。
- 所有访客可一次上传一个或多个现有支持格式的文件（`.xlsx`、`.xlsm`、`.xls` 或 `.csv`）。网站将这一批文件打包为 ZIP，写入私有仓库的 `data/weekly/` 目录。
- 每一批使用独立的时间戳文件名。上传不会删除之前的批次。
- 私有仓库中的 GitHub 凭据从 Streamlit Cloud Secrets 读取，不写入程序文件或浏览器页面。应用通过 GitHub API 提交新批次。
- 网站读取所有历史批次，按上传时间从旧到新合并。相同日期、Planner 和 WHS 的重复记录按现有逻辑保留较新的上传记录。
- 成功提示会说明共享批次已保存。由于提交会触发 Streamlit Cloud 同步代码仓库，其他访客刷新网站后即可看到累计后的数据。

## 上传前检查与失败处理

- 上传前检查每个文件能否被当前应用读取；无法读取的批次不提交，原有共享数据保持不变。
- GitHub 凭据缺失或提交失败时，显示提交错误信息；不把授权令牌显示在界面中。
- 没有历史数据时，访客看到引导首次上传的空状态。

## 首次部署配置

Streamlit Cloud 的 Secrets 需要一个仅允许访问该私有仓库内容的 GitHub 写入凭据，访客无需输入密码或令牌。具体字段名与设置步骤会随实现一并写入部署说明。令牌不通过聊天消息收集。

## 验收标准

1. 访客打开网站能查看共享的累计 KPI 数据，并能直接使用共享上传入口。
2. 访客可以上传一个或多个工作簿并确认提交，无需管理员验证。
3. 新批次写入私有仓库且保留已有批次；重新部署或刷新后仍可读取所有批次。
4. 多个批次按时间合并，重复的日期、Planner、WHS 组合采用较新数据。
5. 无效文件或提交失败不会删除或覆盖已有历史数据。
6. KPI 工作簿不会放入公开仓库；公开网站展示的数据仍对所有访客可见。

## 不在本次范围

- 登录账号、逐用户权限管理或个人上传空间。
- 删除历史批次、回滚指定批次或编辑已提交数据。
- 修改现有 KPI 指标口径、图表或导出功能。
